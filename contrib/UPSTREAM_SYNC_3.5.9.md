## 冲突与定制能力

- 合并的 5 处冲突逐项解决：保留定制发布工作流、Electron 更新器和客户端版本来源；
  设置接口保留会话模式校验与现有 SQL 参数顺序，追加上游 `hoverActionSet`，避免错存偏好。
- 草稿 Bcc 补丁的测试冲突同时保留定制会话模式初始化及上游 Drafts 文件夹场景。
- 会话卡片的附件、星标、邮件头、退订、反垃圾说明、AI、图片允许策略、整组已读、
  跨文件夹计数和 GTD 处理继续保留。
- EML 导出接入现有下载桥，并补齐桌面单封工具栏、手机单封菜单和会话卡片入口。
  Android 只允许配置服务器同源的准确 `raw.eml` 路径，继续拒绝其他源、后缀伪装及任意路径。
- 定制网页桥接保留上游未签名客户端的发布页提示分支，不改变我们自己的应用内更新流程。
- 上游 `macTeamIdentifier` 的无有效 Team ID 处理及对应测试保留。
- 镜像发布沿用 Fork 已有策略：`custom.N` 是本仓库稳定发行通道，继续发布精确标签和 latest；
  未采用上游把所有带连字符标签都排除于 latest 的规则，否则所有定制正式版都会被排除。
- `publish-apps.yml`、Electron 更新器/入口/安装器、签名与版本公共模块、升级脚本、
  Edge Gateway 部署文档均与上一正式版一致。Android keystore 和公开证书指纹保持不变。
- 所有上游锁定依赖版本保持不变。额外依赖仅为原有 electron-updater 及专用传递依赖。

## 验证与升级

本地使用 Node 22、JDK 21 和 Android SDK 36；测试使用替身，不连接真实邮件账户。
后端 109 个测试文件、1,896 项测试通过，lint 与插件边界检查通过；前端 2,366 项测试、lint、
生产构建及单封/会话、手机/桌面 EML 下载回归验证；Android 单元测试 25 项通过，lintDebug 通过。
运行依赖审计无 high/critical；保留与上游一致的后端 1 个、前端 2 个 moderate 项。
前端仍有既有大 bundle 提示，Android 仍有 Gradle 弃用提示及依赖自带 lint baseline。

发布流程要求本地验证后先推送同步分支并进行 `publish=false` 原生构建演练；成功后普通合并
到 `custom/release` 并创建不可变正式标签，由工作流发布 Windows EXE、固定签名 APK/AAB、
更新元数据，以及 amd64/arm64 前后端镜像。具体构建编号和正式产物验证保存在本地发布记录。

服务器沿用既有 `/opt/mailflow` 部署，通过 `mailflow-update 3.5.9-custom.1` 自动备份、
拉取、升级和健康检查。新增迁移 0060、0061 随后端启动执行；服务器升级由用户执行。
本地测试和安装包校验不等同于 Windows/Android 实机连续升级验收。
