# 邮件验证码复制

## 使用

识别到明确验证码时，单封邮件、独立消息窗口、展开的会话邮件，以及应用内新邮件提醒会显示验证码与“复制”按钮。复制失败会提示，并选中验证码供手动复制。前导零会保留。

在“设置 → 行为 → 验证码”中可开启“自动复制验证码”；也可以搜索“验证码”或“clipboard”找到设置。默认关闭，只保存在当前客户端、当前 MailFlow 用户的本地设置中，不会同步开启其他客户端。

自动复制仅在页面可见、有焦点且 MailFlow 已解锁时尝试，目标为 Inbox 中最近 10 分钟内收到的新邮件。会读取完整正文确认候选，不将邮件标记已读；同一批新邮件最多处理五封，并只复制最新一封可明确识别的单个验证码。静默通知规则、历史同步、重复消息、多个候选、正文超限或正文读取失败不会自动复制。

自动复制会覆盖系统剪贴板。浏览器或系统拒绝写入时会保留手动入口，不尝试绕过权限。应用关闭、手机后台、系统通知栏中的复制动作和键盘自动填充不属于本版能力。

## 识别方式

由前端本地多信号规则识别，不调用 AI 或第三方验证码服务。综合判断中英文身份验证/登录语境、附近的输入或使用指令、数字或字母数字格式、有效期描述，以及 HTML 中独立或突出显示的代码块。支持“安全代码”“security code”等明确标签，也处理没有明确标签的验证操作描述。处理 HTML 时先移除资源及事件属性，并排除隐藏内容、脚本和被引用的旧邮件。

手动入口可以显示有合理语境的候选。自动复制要求整体只有一个高把握候选；仅有独立数字或突出版式不能满足自动复制要求，其他中等把握候选也不会被忽略后制造“唯一”结果。

- `您的验证码：001234`：保留 `001234`。
- `Your verification code is A7B9C2`：提供复制按钮。
- `Enter 046281 to finish signing in. Expires in 10 minutes.`：结合验证操作描述识别。
- `Verification code: 123456 or 654321`：显示两个候选，由用户手动选择。
- 普通订单号、日期、电话号码、优惠码不应作为验证码。
- 同时存在的纯文本和 HTML 正文分别识别并去重；两者给出不同验证码时保留多个候选，不自动复制。

识别有意保守，无法保证覆盖所有邮件模板，也不判断验证码是否已被服务商撤销或过期。每个字段最多扫描 48,000 字符；自动复制遇到任何参与识别的字段超限时会跳过，而不会根据截断内容推断唯一性。

## 数据与异步处理

不将验证码写入 localStorage、诊断事件或日志。自动处理只在内存保留有限的消息 ID 去重记录。锁屏、登录身份变化、开关变化和组件卸载会使旧任务失效；新事件与剪贴板写入按顺序处理，避免迟到正文把旧码覆盖到新码上。

手动复制使用现有通用剪贴板工具，并在回退前再次检查用户、锁屏和邮件范围。已交给操作系统的异步剪贴板写入无法撤回，因此不会通过清空剪贴板来“回滚”。

## 主要实现

- `frontend/src/utils/verificationCodes.js`：本地识别和引用过滤。
- `frontend/src/components/VerificationCodeNotice.jsx`：共享展示与手动复制。
- `frontend/src/utils/verificationCodeAutoCopy.js`：新邮件自动复制与取消处理。
- `frontend/src/utils/verificationCodePreferences.js`：按用户隔离的客户端开关。
- `frontend/src/hooks/useWebSocket.js`：新邮件事件接入。
- `frontend/src/hooks/useVerificationCodePreferences.js`：设置开关状态同步。

功能不需要数据库迁移或额外服务，不修改原生登录桥、安装器或更新器。更新后的服务器前端部署后即可加载新网页功能；各平台是否允许自动写剪贴板仍由系统决定。
